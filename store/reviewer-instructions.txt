Scrollout 1.0.6 — test instructions

No account, credentials, payment, subscription, server connection, or special entitlement is required.

1. Install the submitted package in desktop Chrome 120 or newer and pin Scrollout.
2. Open an ordinary scrollable HTTPS page, such as https://developer.chrome.com/docs/extensions/ . Keep that source tab active.
3. Click the Scrollout toolbar icon once. The icon shows progress while the page scrolls. The editor opens automatically after capture completes.
4. Choose Draw or Highlight and drag on the screenshot. Add an arrow, shape, or text. Select an annotation to move/resize it; Delete removes it. Ctrl+Z undoes an edit, Ctrl+Shift+Z redoes it.
5. Choose Crop, drag a region, then Apply crop or press Enter. Undo restores the previous crop.
6. Choose Redact and drag a black box. Redaction is fully opaque. Exported pixels are flattened; originals remain available only in the temporary editor for undo.
7. Open Export and save PNG, JPEG, or PDF. PDF output uses A4 pages. Click Copy image, or right-click the screenshot and choose Copy image, to write the full edited crop as PNG to the clipboard. Very large images are split into numbered parts in one ZIP; oversized clipboard copies show an explanatory error.
8. Reload an editor to verify the saved temporary document survives. Closing or navigating away from the last editor for that capture removes the temporary capture. Browser restart/extension reload expires old captures; the next worker initialization removes orphan data.
9. On a long source page, invoke the toolbar a second time or press Escape on the source page to cancel. Switching tabs, manual scrolling, navigation, and viewport changes also cancel and restore the page.

Expected boundaries: chrome:// pages, the Chrome Web Store, some built-in viewers, and other protected pages can reject capture. A large, fully visible main panel is captured when the document itself does not scroll. Other panels, small widgets, and embedded frames retain their visible contents. Infinite feeds stop at their initial measured dimensions. Local file capture depends on Chrome's separate Allow access to file URLs setting.

All capture/edit processing is local. No remote executable code, analytics, screenshots upload endpoint, or backend is used. Help includes version information, optional release-metadata checks from one static HTTPS file, and instructions for updating unpacked installs. Capture information is never included in a release request. The only permissions are activeTab, scripting, storage, and clipboardWrite.

Version 1.0.6 was validated on Windows with Chromium 153.0.8010.12: all 31 unit and 49 browser checks passed, and the full dependency audit found zero known vulnerabilities. Right-click copy is tested with an actual paste into a separate page, full cropped dimensions, offscreen pixels, annotations, opaque fractional redactions, and pixel equality with PNG export. The unmodified production build passes using its four existing permissions. Menu keyboard controls, outside clicks, scrolling, narrow windows, and oversized-copy errors are covered. Other capture, redaction, export, CSP, ownership, interruption, and update checks pass. Test profiles now load each extension once to avoid a startup/CDP loader race. The build targets Chrome 120, but these new clipboard flows have not been runtime-tested on 120. This is internal QA, not an independent security certification.
